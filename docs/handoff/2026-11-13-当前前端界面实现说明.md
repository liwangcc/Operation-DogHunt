## 阅读范围与结论

用户希望了解当前前端界面怎样实现。本次以当前工作区源码为准，读取代码地图、近期交接、入口与路由、公共布局、样式、状态、主要页面及 3D/图表关键入口。当前工作区已有三页深色方案等未提交改动，本次没有修改业务源码或整理这些改动。

- 技术组合为 Vue 3、TypeScript、Vue Router、Vite、Three.js。页面组件自行编写，当前 package.json 没有引入通用 UI 或图表库。
- main.ts 装入 App.vue 与全局样式。App.vue 将全屏启动页与 AppShell 内页分开；KeepAlive 只缓存聊天页，保留切页前的对话与输入，不代表刷新后持久保存。
- 路由首次打开先进入 /welcome，sessionStorage 记录本标签页是否已进入及原目标地址。业务页通过 Vue Router 切换，多数页面按需加载。
- StartupView 动态加载 startup/stage.ts；Three.js 持续绘制场景，提供镜头、点选、材质、后期和画质调整。3v3 比赛位于 game/，是独立模拟与渲染模块。
- AppShell 共用导航、状态条、快捷命令面板与背景。tokens.css 管颜色字体等变量，ui.css 管共用按钮面板等样式，组件内 scoped CSS 管局部布局。内页雨夜使用原生 WebGL，失败时退回静态背景；窄屏通过 CSS 改布局。
- stores/ 使用 Vue ref、reactive、computed 共享运行状态、选场与偏好，没有额外状态库。preferences 用 localStorage 保存本机显示偏好。
- 聊天通过 api/chat.ts 请求后端；发送历史消息与可选比赛/平台标识，等待完整回复后展示。前端不直接保存模型密钥。
- 比赛页读取后端已保存盘口；手动更新另走刷新请求。演示开启且真实盘口为空时显示虚构联赛，存在真实盘口时优先真实数据。
- 记录与统计共用 predictionRecords 和 useRecordScope，domain/ 负责结算汇总。当前记录来自 demo/，统计由这些记录计算；EquityChart 使用 SVG 绘制曲线。CSV 导出和筛选已写入界面逻辑，正式记录保存与赛果接口未接入。
- 记忆页面操作的是本页内存中的演示对象；设置保存本机显示偏好，后台配置只读。

## 为什么要区分实现与数据来源

界面有完整组件、筛选、抽屉和统计计算，不等于正式数据闭环已经完成。应分别说明真实聊天/盘口连接、演示记录/统计/记忆、以及本机偏好存储，避免将示例数值当成真实战绩。
