# 中转模型聊天接入

日期：2026-11-11（Asia/Shanghai）  
状态：✅完成本轮模型 API 接入与网页真实调用；自动取数分析、正式预测保存仍待开发。

## 用户要什么，本轮做到哪里

用户要求先接入当前聊天使用的中转站模型，为比赛预测打通模型调用。只读核对本机当前配置，模型标识为 `gpt-6.1-sol`，中转 API 根地址为 `https://relay.example`，接口类型为 Responses。

已把当前连接信息复制到后端私有 `backend/.env`，不修改 Codex 配置，不把认证值放进前端、文档或普通日志。配置文件以不覆盖已有文件的方式创建，权限为 `600`，写入后解析核对一致。配置是独立副本，Codex 后续切换模型或刷新认证不会自动同步到网站。

网页可以发送问题、携带当前页历史继续追问、开始新对话；等待时禁止重复发送，失败保留输入并显示错误。本轮不实现数据库，离开聊天页或刷新会清空对话。

## 为什么这样接

- 保持现有 Vue → FastAPI → 外部服务的结构，由后端访问中转站。中转需要额外认证信息，只有模型 Key 不足以完整复用当前连接。
- 用 httpx 作为后端 HTTP 客户端，不绑定官方模型列表或写死 `/v1`。程序只在供应商给出的根地址后添加 `/responses`，避免误把当前根地址改成不支持的路由。
- 后端读取 Responses 流，收到完整完成事件才交付回答；也兼容供应商返回普通 JSON。半截流、失败或截断不能当成功。本阶段网页整体显示答案，不逐字显示。
- 不自动重试，默认总超时 120 秒，默认最多输出 4096 tokens；单进程同时只执行一个模型请求，避免重复点击产生多笔费用。超时不能保证供应商未计费。
- 服务端补充北京时间和 NBA 分析要求。模型目前没有数据查询工具，必须区分用户资料、假设和未知数据，不编造实时赛程、伤病或盘口，不把赢球等同于赢盘。

## 代码与使用入口

- `backend/app/integrations/llm.py`：中转请求、完整返回解析、超时与脱敏错误；不跟随重定向、不自动重试。
- `backend/app/services/chat/service.py`：系统要求、当前页历史、单进程并发限制。
- `backend/app/api/routes/chat.py`：`GET /api/v1/model` 只查配置、不调用模型；`POST /api/v1/chat` 返回回答、配置模型名及可用 token 用量。
- `backend/app/schemas/chat.py`：最多 41 条交替消息，最后一条 user；单条 12000 字符、合计 60000 字符，不允许客户端提交 system 消息。
- `frontend/src/views/ChatView.vue` 与 `frontend/src/api/chat.ts`：模型配置状态、发送、等待、历史、错误和新对话；回答按纯文本显示。
- 依赖与锁文件已更新；`README.md` 和 `backend/.env.example` 说明配置、限额及启动方式。修改 `.env` 后需重启后端。

已按 codebase-map 增量核对前后端子块并更新 CODEBASE 父块，没有把本轮更新写成全库重新验收。

## 实际验证结果

1. 通过网站 ASGI 接口执行真实中转请求：`CHAT HTTP 200`，返回“模型连接成功。”；模型 `gpt-6.1-sol`，输入 246、输出 8 tokens。这是本次简短请求用量，不是全部测试调用总量或费用。
2. 浏览器实际发送，看到等待状态，再看到“网页模型连接成功。”，输入和按钮恢复可用。
3. 最终网页发送假设盘口问题：甲队让 5.5、最终赢 3 分。模型实际回复：“假设甲队让 5.5 分，最终只赢 3 分，甲队不算赢盘，而是输盘。比赛胜负上甲队获胜，但让分盘由受让 5.5 分的乙队赢盘。”这是规则示例，不是真实比赛预测。[验证截图](assets/2026-11-11-模型聊天验证.png)。
4. `cd backend && .venv/bin/python -m unittest discover -s tests -v`：`Ran 10 tests in 0.045s / OK`。离线覆盖认证和额度失败、总超时错误映射、半截流、无重试、输入边界、上下文传递、并发与状态接口不外露密钥；测试不调用付费服务。
5. `npm run build` 包含 TypeScript 检查；初次 52 modules，保留同期盘口页面后最终 `63 modules transformed / built in 104ms`。

这些结果证明当前模型连接和聊天入口可用，不证明比赛预测准确率、自动收集资料、持久化或外部服务持续可用。

## 踩过的坑和边界

- 项目没有 Git，状态检查返回 `not a git repository`，与原记录一致；未初始化、提交或推送。
- 官方文档搜索返回 503；沙箱内直接请求遇到 DNS 限制；受控请求的一个官方地址 404，另一个入口 403。未取得官方页面，接入兼容性以当前中转实际请求为证，没有把文档搜索故障描述成已修复。
- 本地命令访问端口被沙箱拒绝，改用应用内浏览器验证。真实中转验证使用受控网络执行。
- 运行中的后端在 `.env` 创建前缓存了空配置，网页最初显示未配置；触发已有开发服务重新加载后，“检查配置”显示 `gpt-6.1-sol` 已配置。新配置文件不会自动刷新已缓存的 Settings。
- 验证期间本轮之外的任务新增了盘口页面和接口，引发开发页面自动更新并清空测试对话。保留这些改动，最终重新构建、验证并截图；没有点击“更新盘口”或调用体育取数接口。
- 当前网页盘口展示和模型聊天是两条独立链路。模型不会自动读取卡片，不会自行获取实时赛程或伤病；页面已明确提示这点。同期盘口任务的取数实现、费用与验收由该任务记录。
