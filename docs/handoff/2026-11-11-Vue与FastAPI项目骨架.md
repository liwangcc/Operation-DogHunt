# Vue 与 FastAPI 项目骨架

日期：2026-11-11（Asia/Shanghai）  
状态：✅完成本轮目录与可运行骨架；业务功能仍待开发。

## 用户目标与已确认选择

用户要求搭建整个项目的文件目录与前后端框架，明确前端使用 Vue、后端使用 FastAPI。在进一步确认中，用户选择 TypeScript。

本轮交付前后端可启动的最小骨架、页面入口、真实连通检查、依赖锁文件、启动命令和目录说明。没有将本轮范围扩大为完整 NBA Agent。

## 结构与为什么这样选

前后端分别放在 `frontend/` 和 `backend/`，仍归同一项目管理。保留已有 `scripts/fetch_nba_odds.py`、`data/odds/`、需求文档和根目录 `.env.local`，避免整理目录时破坏已验证的手动采集流程。

前端使用 Vue 3、TypeScript、Vite、Vue Router。聊天首页是主入口，预测记录、效果统计、长期记忆、设置各有预留页面，未知地址有 404 页面。浏览器只通过 `/api` 请求后端，Vite 在本机转发到 FastAPI，降低开发时跨站配置的复杂度。

后端按接口入口、配置、数据格式、业务流程、外部服务、存储与任务划分。聊天、盘口、分析、记忆的业务目录已经创建；数据库连接、数据模型、集中读写和后台任务仅保留有说明的 Python 包。没有安装数据库驱动、GPT SDK、Pinia 或任务队列，避免骨架提前绑定尚未讨论的持久化和执行方案。

实际实现的后端接口只有 `GET /api/v1/health`。其返回代表应用进程可以响应，不验证数据库、GPT、盘口供应商或业务准备状态。没有创建返回假成功的聊天、记忆、预测接口。

前端的连接状态来自实际请求，5 秒超时，不自动重试，可手动检查；会核对返回格式。聊天输入和发送按钮明确停用，页面标注业务待开发，不返回模拟 AI 分析。

## 使用入口

- 根目录 `README.md`：启动、配置、构建和现有盘口工具的说明。
- `docs/项目目录说明.md`：目录职责、后续功能放置位置及边界。
- `make setup`：按锁文件安装依赖。
- 两个终端分别执行 `make backend` 与 `make frontend`。
- 页面：`http://127.0.0.1:5173/`。
- 后端：`http://127.0.0.1:8000/api/v1/health`。
- 接口说明：`http://127.0.0.1:8000/api/docs`。
- `make build`：TypeScript 检查和前端构建。

后端 `.env` 是可选配置，默认即可启动。前端可选 `.env.local` 只设置本地开发转发地址。已有盘口 Key 仍在根目录 `.env.local`，本轮没有读取或改动该文件，也没有执行取数脚本。

当前启动命令仅监听 `127.0.0.1`，未部署公网。上线还需要认证、生产服务和路由转发配置。FastAPI 文档界面使用公共 CDN 的 Swagger UI 资源，离线可读 `/api/openapi.json`；Vue 页面本身使用本地打包资源。

## 踩过的坑与失败路径

1. 通用官方文档查询工具返回 `503 Service Unavailable`，已立即向用户说明，没有重复调用。改为浏览器直接读取 Vue 起步文档和 FastAPI 多文件组织文档成功。这不代表此前中转搜索故障已经恢复。
2. 浏览器验证时，标题定位使用了该工具未支持的 `level` 选项，导致两个标题同时匹配。已说明错误，改为标题文字精确匹配成功。这个失败是检查指令的问题，不是项目页面运行错误。
3. 依赖下载与本机服务启动使用受控执行授权；缓存定向到临时目录，未升级全局 Node、npm 或 Python。

本轮未删除或移动用户文件，没有初始化 Git、提交、推送或发布；仅追加 `.gitignore` 规则和交接索引，其他产出都是新文件。
