## 原因与依据

1. 两条开发线分别改写过这三个页面。`docs/codebase/frontend.md` 的“提交说明（2026-11-12）”明确记录，整理 PR 时采用目标 dev 原有的个人选场复盘、浅色统计、设置按钮框架，没有采用来源开发线重做的三个页面。
2. 当前 HEAD 为 `acce9c3`。执行 `git diff 10ea61a HEAD -- frontend/src/views/RecordsView.vue frontend/src/views/StatisticsView.vue frontend/src/views/SettingsView.vue` 无输出，退出码 0：三个页面文件与 PR 合并前目标基准完全一致。页面内部仍直接指定浅色卡片、绿色按钮及深色文字。
3. `frontend/src/styles/tokens.css` 定义全站深色背景、浅色文字与青色强调色；公共外壳和改版后的页面使用这套设计。
4. 审查修正提交 `446a4b0` 在 `frontend/src/components/layout/AppShell.vue` 增加 `lightPage`，明确匹配 records、statistics、settings，并设置 `color-scheme: light`、文字 `#203a36`、背景 `#f7f9f7`。目的是让保留的旧页面在新外壳中可读，并未统一风格。
5. 路由当前仍直接加载上述三个原有 View。仓库留下另一版记录/统计的部分组件和数据模块，并不表示页面已经切换到另一版。

## 影响与建议

这是合并取舍留下的视觉不一致；当前源码足以解释截图，不需要先归因于缓存或重启失败。上轮审查处理了可读性问题，却保留了两套视觉设计。

建议后续保留当前三页的功能、内容和交互，将页面及相关子组件的颜色、卡片、按钮、表单和图表统一到现有深色设计变量。仅删除 AppShell 的浅色背景不够：旧页面仍有大量固定颜色，容易重新出现深色文字落在深色背景上的问题。直接换成另一版页面则涉及功能和数据行为差异，应先确认范围。
