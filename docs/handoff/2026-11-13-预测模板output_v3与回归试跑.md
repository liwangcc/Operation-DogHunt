# 预测模板 output_v3 与回归试跑

日期：2026-11-13（Asia/Shanghai）
状态：✅ chat_output_v3 已生效，E-001、E-009 真实试跑均通过；网页与 HTTP 接口未验证。

## 起因

尼克斯 @ 步行者选场预测只有结论和两条一句话依据：没说预计范围怎么来的，两个“把握低”都没给原因（`issues.md` I-004）。另外 chat_output_v2 的分档没写明“休息差”算哪档，那场让分本应可到“中”。

## 改动

- 新增 `backend/app/prompts/chat/chat_output_v3.md`，锁文件 `active` 切换到它；静态提示词 3711 → 4465 字，哈希前 12 位 `b84eb3eb3d25`。
- 模板：结论行每个把握加一句原因；让分、大小分各有因素表（含缺失项）、“预计怎么来的”、“把握说明”；单场 700 字以内（表格不计）。
- 分档：“高”要求 B 级资料或盘口明显移动且伤病已知；“中”明确含休息差；“低”为 1 分以内报价差、只有 C 级、因素矛盾或没有因素。
- 记录：CHANGELOG、issues I-004、README 版本表；eval_cases 更新 E-001 期望并新增 E-009；代码地图后端子块与父块。

## 回归试跑

- 模型 `gpt-6.1-sol`，思考强度 `high`，经项目中转；固定快照 S-001，时间固定为 S-001 的 `now`，选场湖人 @ 掘金、DraftKings；`load_history` 返回空。
- 调用方式：`backend/` 下临时脚本直接调用 `services.chat.service.chat`，未经 HTTP 和浏览器。
- 调用次数：E-001、E-009 各 1 次。第一次运行在 E-001 完成后被中断，E-009 单独补跑；E-001 没有重跑。E-009 用量：输入 3775 / 输出 1326 tokens，45.6 秒；E-001 的用量因中断未打印。

## 观察

- E-001 只有报价差时，模型把预计分差和总分也朝倾向一侧调了 0.25、0.5 分，同时又写“报价优惠不代表球队实力增强”。method_v4 第 6 条允许调 0 分，E-009 的总分就没调。只出现一次，暂不登记问题；再出现可考虑在 method 写明“报价差只决定选边，不调整预计”。
- 因素表“资料”列在缺失时写“缺失”或“A：赛程不可用”，不统一，不影响阅读。
- E-009 输出 1326 tokens，离 4096 上限较远，这次没有截断。
