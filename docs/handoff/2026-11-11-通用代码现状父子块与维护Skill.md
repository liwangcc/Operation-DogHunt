## 用户选择与交付入口

用户希望用一份有父块和子块的说明书了解代码情况：父块总结，子块记录具体实现，并由 Skill 持续维护。用户明确选择“做成通用模板，之后用于其他代码库”，更新方式为“代码有改动时调用 Skill，需要时也能手动更新”。

- [CODEBASE.md](../../CODEBASE.md) 为当前项目父块，链接前端、后端和独立盘口工具三个子块。
- 子块在 `docs/codebase/`，记录职责、源码入口、依赖、实现与缺口、验证来源和边界。
- [codebase-map Skill](../../.agents/skills/codebase-map/SKILL.md) 随附父块和子块模板，通用规则不绑定 NBA、语言或框架。
- 根目录 `AGENTS.md` 补充 AI 开发后同步要求，不改全局协作配置。

## 为什么这样选

通用流程与项目实例分开存放：Skill 和 `assets/` 模板负责可复用结构，`CODEBASE.md` 和子块只记录目标代码库的事实。迁移时复制完整 `codebase-map/` 到另一仓库 `.agents/skills/`，调用初始化即可，避免把 NBA 的实现状态带到别的项目。

父块保持短，详细依据只在子块展开；维护顺序为先核对子块，再同步父块。实现状态和运行验证分别记录，避免把目录预留、需求目标、读到的函数误写成已经可用的业务功能。

按用户选择采用开发任务触发和手动调用。没有创建定时任务或文件监听器；用户在编辑器中的手动改动，需要下次相关开发任务或手动调用时同步。代码地图自身和交接更新不再触发新一轮维护，避免递归更新。

## 遇到的问题与处理

1. 当前目录没有 Git，读取状态返回 `fatal: not a git repository`。未初始化 Git，改为直接核对文件。Skill 同时支持有 Git 的增量核对和无 Git 的文件核对，部分检查不刷新全量核对日期。
2. 官方资料搜索返回 `503 Service Unavailable`，没有取得官方页面。使用本机 Skill 创建规范完成文件，不声称已得到官方页面验证。已有搜索故障交接的 ⚠️ 状态保留。
3. 首次 Skill 校验因缺少 PyYAML 返回 `ModuleNotFoundError: No module named 'yaml'`。在本机 uv 缓存找到已有副本，通过临时 `PYTHONPATH` 运行官方校验器成功；未下载安装依赖，未修改项目 Python 环境。
4. 项目 `.agents/` 属于受保护目录，先在临时目录准备并校验具体四个文件，再通过受控执行创建新的 Skill 目录。目标存在时停止，不覆盖已有 Skill。
5. 本次交接已插入 INDEX 顶部，随后另一任务新增了更晚的交接，导致“必须仍在第 1 行”的收尾断言失败。保留索引现有时间顺序，最终检查改为确认本次条目唯一存在、链接有效且其他记录保留，不为争夺首行反复重排并行任务的交接。

## 下一次怎么用

在当前项目说“用 $codebase-map 同步本次改动”做增量维护，或说“用 $codebase-map 检查整个项目的说明书”核对全量。新代码库先复制整个 Skill 目录，再调用初始化；如果也需要开发后同步，可按 Skill 中的片段追加到目标仓库原有 `AGENTS.md`，保留原规则。

项目业务仍待实现不是本次文档维护的阻塞项；后续实现时按模块同步代码现状和验证记录。父子块文档描述开发项目，不是网站内部长期记忆功能的实现。
