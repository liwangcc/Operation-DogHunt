## 用户确认的流程

用户希望写完每场复盘后先积累归档，随时打开查看，等材料足够再主动分析和决定策略调整。同时要求与设置页并行开发。延续此前只做 UI、预测数据以后接入的范围，本轮演示归档操作仅保留在当前页面内存，不保存到浏览器或服务器；刷新和离开页面后恢复示例。页面、按钮与成功提示均明确这一点。

## 设计与使用方式

预测记录页内增加“选场记录 / 复盘档案”切换，避免修改公共导航。已结算的示例比赛可填写一句话发现、复盘原文和观察标签；原文空白时按钮禁用。归档后自动打开对应档案，本页待复盘和已复盘数量同步变化。一份档案按比赛关联预测，不把同场让分与大小分当成两份互不相干的比赛档案。

档案默认展示两份虚构示例，可按比赛日期、玩法、标签、球队及复盘全文查找；搜索包含后续补充。详情显示当时预测、盘口赔率、赛果示例、复盘原文与补充时间线，并可回到对应预测。补充以新条目追加，保留最初原文；不自动提炼因果或修改策略。

多选复盘后可打开整理清单，清单明确显示全部所选材料；筛选不会悄悄丢掉已勾选项。汇总分析按钮禁用并标后续接入。归档、查看与整理三件事先在 UI 中连起来，分析和策略版本留待后续定义。示例/空白切换不丢失当前页已归档内容；空白时清理档案筛选与勾选，刷新或离页会重置全部演示状态。

## 踩坑与后续接入

自动检查“查看预测”时，精确名称忽略了按钮末尾箭头，首次匹配失败；按当前页面完整名称重新定位后通过，没有更改业务来适配检查。空白预览起初会残留已不存在的日期选项，已在档案为空时清理筛选和勾选；修正后重新检查并构建。

演示 matchKey 使用比赛日期与主客队组成，真实接入应使用供应商赛事标识。ReviewEntry、ReviewDraft 仅为 UI 内部格式，不是已确定的数据库表或后端协议。真实保存时需补账号归属、赛事标识、持久化与错误状态、时间来源、追加历史、预测关联及多人隔离；汇总分析需保留所选复盘材料和分析版本，策略调整由用户另行确认。
