# 效果统计浅色 UI

日期：2026-11-12（Asia/Shanghai）
状态：✅完成本轮 UI 范围；正式预测、赛果与真实统计数据后续接入。

## 用户目标与结果

用户在浅色、深色对比后选择 A 浅色研究看板，确认第一眼看整体表现和收益走势，要求与预测记录 UI 同步进行。本轮将 /statistics 从占位页改为可交互页面，沿用现有深绿侧栏与浅色内容风格，不增加依赖、不修改后端。

首屏为累计模拟收益、模拟收益率、整体命中率和已结算选择四卡，以及主要面积的累计收益曲线。次级区域为让分/大小分比较、结算状态分布、观望和数据不足。支持最近 7 天、30 天、全部时间、玩法、版本和来源筛选，曲线可悬停及用左右方向键、Home/End 查看每日明细。页面可切换“正式数据待接入”说明和无匹配样本状态，比例无样本时显示横线。

## 代码与协作边界

- frontend/src/views/StatisticsView.vue：页面结构、筛选、派生指标、空状态与统计口径说明，样式全部 scoped，避免影响同期页面。
- frontend/src/features/statistics/data.ts：仅用于 UI 的演示选择及 summarize、dailyProfits 纯计算函数。
- frontend/src/features/statistics/ProfitChart.vue：原生 SVG 曲线，以 ResizeObserver 适应容器；卸载时断开观察器。
- 仅通过既有 /records 导航连接预测记录页；没有修改另一聊天开发的 RecordsView.vue、data/recordPreview.ts、公共样式或路由。已保留其新增文档与代码地图内容。
- 使用 $codebase-map 增量同步 docs/codebase/frontend.md 后同步 CODEBASE.md；后端、盘口子块及全量核对日期不变。

两页使用不同演示数据，统计页的 100 笔不能与预测记录页的 6 条示例核账。真实数据阶段必须统一记录接口、选择标识、玩法/版本/来源字段、记录日期与结算日期口径，并用同一数据源供列表和统计使用；当前 StatisticsRecord 是统计演示内部类型，不是已约定的后端接口。

## 选择理由与统计边界

选浅色因为用户已确认 A，复用现有页面视觉能够减少页面切换割裂感。优先累计收益与走势，因为用户明确整体表现是首屏重点；玩法对比保留在下方。使用现有 Vue 与 SVG，当前规模无需引入图表库。

所有数字明确标为演示。演示锚定日期为 2026-11-12，默认 30 天为 2026-10-14 至 2026-11-12，不伪装成随实际日期更新的历史数据。按每个选择模拟投入 1 单位；赢盘净收益为十进制赔率减 1，输盘为 −1，走盘为 0。命中率分母为赢输笔数，模拟 ROI 分母为已结算有效投入，包含走盘，不含取消、待结算、观望及数据不足。两个玩法按选择分别计数，不当作比赛数。

演示记录的记录日与结算日相同；曲线从筛选区间重新累计，不继承之前收益。两个玩法比较卡始终保留同一时间/版本/来源下的对比，主看板与分布跟随所选玩法。筛选离页或刷新后重置，未实现持久化。当前没有请求统计接口，因此没有伪造加载、接口成功或重试行为。

## 实际验证

- 最终执行 npm --prefix frontend run build：类型检查通过，73 modules transformed，built in 131ms；包含同期预测记录 UI。
- 用已安装 TypeScript 编译统计数据模块后运行 Node assert 离线核对：100 settled / 58 wins / 42 losses / +8.6 units / 8.6% ROI；让分 +6.2、大小分 +2.4；日曲线终点与总收益相等；走盘计入投入、取消/待结算排除、零分母、7 天范围和空人工补录样本通过。
- 浏览器实际切换让分得到 50 笔、60.0%、+6.2 单位；再切近 7 天得到 11 笔、7 赢 4 输、+2.3 单位、20.9% ROI。版本 v2 筛选、人工补录无匹配状态、重置和正式待接入状态通过。
- Home/End 查看曲线起止日分别显示 2026/10/14 累计 −0.6 与 2026/11/12 累计 +8.6；“查看预测记录”跳到同期已开发的 /records。

- 未发起模型聊天、外部盘口更新或赛果请求，未提交、推送、发布；没有验证真实记录保存或线上统计业务。

## 遇到的问题与处理

读取 frontend/tsconfig.app.json 时不存在，改读项目实际的 frontend/tsconfig.json，没有新建配置。首次离线断言将浮点计算的 57.99999999999999 与 58 严格比较而失败，检查改用 1e-9 容差；页面仍按一位小数显示。浏览器通过标签查找嵌套下拉框时未找到精确名称，为策略和来源 select 增加明确 aria-label 后复验通过。尝试对非可聚焦 h2 发送 Tab 失败，改用页面滚动完成手机检查，没有因此改业务代码。
