# 首页 NBA 比赛与盘口展示

日期：2026-11-11（Asia/Shanghai）  
状态：✅完成首页展示与手动更新；数据覆盖和模型联动边界见下文。

## 用户目标与使用方式

用户希望在网站主界面直接看到 NBA 近期比赛、开赛时间、让分与大小分。用户明确选择“现在先手动更新”。打开 `http://127.0.0.1:5173/`，首页聊天上方是比赛区；默认近 7 天，可切换今天、明天、全部已开盘。每张卡片的“报价平台”可切换供应商，盘口与两侧赔率同步变化。

“重新读取”只访问已保存的数据，不消耗外部接口额度；“更新盘口”向 The Odds API 请求一次，通常两个市场消耗 2 credits，以返回为准。页面展示上次采集时间、报价时间和额度记录，没有定时取数。

## 为什么这样实现

已有 `scripts/fetch_nba_odds.py` 已验证真实取数，继续复用其密钥加载、15 秒超时、不跟随重定向和新建快照逻辑，避免引入第二种取数方式。后端新增固定文件路径适配层，不移动或改写原脚本；部署必须包含脚本及可写的 `data/odds/`。

另一个聊天“接入模型预测比赛 API”同时修改同一项目。比赛功能做成独立 `MatchBoard`，仅在 `frontend/src/App.vue` 装入首页，在 `backend/app/api/router.py` 增量注册盘口路由，未改写其 `ChatView`、模型配置与认证文件。比赛卡片尚未自动传给模型；模型回答仍依据用户输入的资料。

现有来源只返回已开盘的比赛，无法证明全天完整赛程。因此页面明确标示覆盖范围；今天无数据不写成“今天没有比赛”。本次 14 场中，近 7 天有 10 场，均在北京时间 11 月 12 日上午，另有圣诞节的远期比赛；默认近 7 天避免远期比赛混入日常列表。

盘口按平台和具体选择保存，让分正负号始终跟随球队，不根据数组顺序猜主客。大分和小分各自保留盘口数值，缺某侧或某玩法显示暂无报价，不用别的平台数据补齐。默认显示数据源首个平台，不代表推荐或最优盘口。

## 入口与数据

- 前端：`frontend/src/components/odds/MatchBoard.vue`、`MatchCard.vue`、`MarketQuote.vue`、`format.ts`，请求与类型在 `frontend/src/api/odds.ts` 和 `frontend/src/types/odds.ts`。
- 后端：`backend/app/api/routes/odds.py`、`backend/app/services/odds/board.py`、`backend/app/integrations/odds.py`、`backend/app/schemas/odds.py`。
- `GET /api/v1/odds` 只读取最新快照；无文件和损坏文件返回明确状态。不会静默使用更旧文件冒充当前数据。
- `POST /api/v1/odds/refresh` 接受 JSON 请求；进程内互斥与 60 秒间隔防止连点，不自动重试。成功新建 JSON/CSV，失败保留旧文件，网页也保留原先卡片。
- Key 继续由后端从环境变量或根目录 `.env.local` 加载，不输出到前端或日志。本轮未读取、复制或改写真实 Key。
- 采集或报价超过 15 分钟标记待更新；这只是提示阈值，不触发自动请求。已到开赛时间的记录标为赛前快照，不猜比赛进行状态。

## 遇到的问题与处理

1. 项目没有 Git，`git status` 返回 not a git repository；按源码文件增量改动，没有初始化版本库。
2. 命令行直连本机 HTTP 被沙箱拦截，返回 `Operation not permitted`；改用浏览器完成真实页面、取数和更新结果验证，未把离线 TestClient 当真实网络证据。
3. 浏览器桌面检查脚本首次使用未绑定的 browser 变量；绑定已选浏览器后成功，网站本身无该错误。
4. 更新 frontend 子块时并行任务刚修改文档，补丁校验失败，文件没有被覆盖。重新读取最新版，保留模型内容，再补入盘口信息。交接索引同样增量插入，不争夺并行任务的首行顺序。

## 后续边界

当前没有完整赛程、赛果和实时比分；手动更新只获取来源当前覆盖的已开盘比赛。下一步可将所选比赛和同一平台的报价、采集时间作为模型输入。数据库、预测保存、长期记忆不在本次范围内。

刷新冷却与锁只在单进程内生效，独立脚本不受限；当前网站仅本机使用。未来公网部署需认证、共享限流及正确转发，不能把本地防连点当成公网额度保护。

使用 `codebase-map` 已同步前端、后端、盘口三个子块及 `CODEBASE.md`，保留并行模型任务的验证记录，没有改动全量核对基准。
