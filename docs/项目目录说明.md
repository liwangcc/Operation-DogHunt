# 项目目录说明

日期：2026-11-11。已确认技术：Vue 3、TypeScript、FastAPI。

这份目录先把职责放清楚，功能再逐块补齐。前后端在同一个项目里分别启动；没有拆成多个独立服务，也没有引入数据库、任务队列或部署平台。

## 前端：用户看到和操作的部分

```text
frontend/
├── src/
│   ├── main.ts                    启动 Vue，装入页面切换和公共样式
│   ├── App.vue                    整个页面的入口
│   ├── router/index.ts            地址与页面的对应关系
│   ├── views/                     完整页面
│   │   ├── ChatView.vue           聊天首页骨架
│   │   ├── RecordsView.vue        预测记录预留页
│   │   ├── StatisticsView.vue     效果统计预留页
│   │   ├── MemoryView.vue         父子块记忆预留页
│   │   ├── SettingsView.vue       设置预留页
│   │   └── NotFoundView.vue       地址不存在时的页面
│   ├── components/                可以多处使用的小块页面
│   │   ├── layout/AppShell.vue    侧栏和顶部栏
│   │   └── common/                后端连接状态、功能预留提示
│   ├── api/                       与后端交互的请求
│   │   ├── client.ts              共用请求、超时和错误处理
│   │   └── health.ts              后端连通检查和响应格式核对
│   ├── composables/               可重复使用的页面逻辑
│   │   └── useBackendHealth.ts    连接检查状态
│   ├── stores/                    预留跨页面共享状态，尚未引入 Pinia
│   ├── types/api.ts               接口数据的 TypeScript 格式
│   └── styles/main.css            公共样式及手机布局
├── index.html                     网页入口
├── vite.config.ts                 开发服务、路径简称和后台转发
├── tsconfig.json                  TypeScript 检查规则
├── .env.example                   前端开发配置示例，不放密钥
├── package.json                   依赖和常用命令
└── package-lock.json              确定的安装版本
```

上面是项目骨架阶段的目录。之后新增的内容没有逐项补进这张图，当前实际结构以 [前端子块](codebase/frontend.md) 为准；其中 `composables/useBackendHealth.ts` 已并入 `stores/system.ts`，`common/` 里的功能预留提示已随四个预留页一起移除。

例如新增“比赛卡片”：展示组件放 `components/games/`，请求放 `api/games.ts`，数据格式放 `types/`，再由聊天页面使用。不要把全部请求和页面代码塞进 `App.vue`。

只有实际出现跨页面共享状态时再接入 Pinia。当前连接状态属于局部页面逻辑，没有必要先安装一套状态存储。

## 后端：业务处理和数据保存的部分

```text
backend/
├── app/
│   ├── main.py                    创建 FastAPI，注册接口
│   ├── api/
│   │   ├── router.py              汇总 /api/v1 接口
│   │   └── routes/health.py       已实现的连通检查
│   ├── core/config.py            从环境变量和 backend/.env 读配置
│   ├── schemas/health.py          接口输入输出格式
│   ├── services/                  业务流程，以下子目录目前仅预留
│   │   ├── chat/                  聊天接续、比赛选择、上下文
│   │   ├── odds/                  盘口查询和快照
│   │   ├── analysis/              资料组装、分析核对、预测记录
│   │   └── memory/                父子块记忆的保存与召回
│   ├── integrations/              预留外部服务：盘口、GPT 等
│   ├── db/                        预留数据库连接与会话
│   ├── models/                    预留持久化数据结构
│   ├── repositories/              预留集中读写数据库的代码
│   └── tasks/                     预留任务执行、恢复及定期维护
├── tests/                         业务测试预留位置
├── .env.example                   后端配置示例
├── pyproject.toml                 Python 依赖与项目设置
└── uv.lock                        确定的安装版本
```

`__init__.py` 让 Python 能将目录识别为可导入的代码包，预留目录里的文件目前仅说明用途，没有伪装完成的函数。

一次未来的分析请求按职责流动：

```text
Vue 页面 → api/routes 接收请求 → services 组织业务
                                   ├→ integrations 请求外部资料或 GPT
                                   └→ repositories 读写 db/models 对应的数据
```

- `schemas` 是前后端交换的“表格格式”；`models` 是存进数据库的“账本结构”，两者不混用。
- `integrations` 只负责与某个外部服务通信；`services` 决定取什么资料、何时分析、如何核对。
- `tasks` 后续需要持久化任务状态和有限重试。当前没有启动定时任务，也没有声称具备刷新恢复能力。
- `db` 只预留位置，SQLite、PostgreSQL、表结构及迁移工具都还未选择。本轮不凭空决定这些长期方案。

## 现有文件如何衔接

- `scripts/fetch_nba_odds.py` 仍是独立的单次取数工具。未来先把它的取数与整理能力接到 `integrations/` 和 `services/odds/`，再提供网页接口；本轮没有移动脚本或自动执行它。
- `data/odds/` 继续保存原始快照，不作为当前实时盘口。未来其他本地运行数据可放 `data/app/`，已加入忽略规则。
- 根目录 `.env.local` 仍归现有脚本使用。后端目前只读自己的 `.env`，不把根目录真实 Key 自动送进新应用。
- 需求和交接继续放在 `docs/`，可运行代码放在前后端目录。

## 取舍与边界

本轮选择同项目分目录，前端 Vite 开发服务把 `/api` 转发给 FastAPI：启动简单，后续可以独立部署。后端没有额外开放跨站请求权限。

保持依赖精简：暂不引入组件库、全局状态库、数据库驱动、Redis、任务队列或 GPT SDK。这些在对应功能真正落地时选择，避免目录骨架提前绑定未确认方案。

当前可用的是页面切换和真实连接检查；业务页面只是入口。任何后续开发都应继续遵守：先列比赛再选择、不拼接不同平台报价、不把历史数据当实时、不在保存失败时声称已记住。

参考官方说明：[Vue 项目起步](https://vuejs.org/guide/quick-start.html)、[FastAPI 多文件组织](https://fastapi.tiangolo.com/tutorial/bigger-applications/)。依赖的具体版本以本项目锁文件为准。
