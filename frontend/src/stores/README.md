# 跨页面状态

这里放几个页面都要用到的状态，都用 Vue 自带的 `ref` / `reactive` / `computed`，没有引入 Pinia（Vue 常用的状态管理工具）。

| 文件 | 管什么 | 保存在哪里 |
| --- | --- | --- |
| `system.ts` | 后端连接、模型是否已配置、最新保存的盘口快照，以及每秒走一次的时钟（倒计时、北京时间、过期标记都靠它）。三项检查都只读本机后端；只有 `refreshBoard` 会向盘口供应商取数并消耗额度，只在用户点“更新盘口”时调用 | 内存，刷新后重新读取 |
| `oddsSelection.ts` | 比赛页与聊天之间共享的所选比赛标识、平台标识和展示标签；不保存报价，发送时由后端读取最新快照。另有一个标记，表示从演示比赛点了“交给 AI 分析” | 内存；取消选场、新对话或刷新后清空 |
| `preferences.ts` | 本机显示偏好：赔率格式、默认报价平台、动态背景、演示数据开关 | 浏览器的 `localStorage`（长期保存在这台设备的浏览器里）；读出时逐项校验，存储不可用时只在本次打开期间有效 |
| `demo.ts` | 演示数据的开关和取用：哪些页面此刻在用虚构的“沙盘联赛”数据。真实数据存在时永远优先用真实数据 | 开关本身在 `preferences.ts` |
| `records.ts` | RecordsView 与 StatisticsView 共用的预测记录来源；演示开启时读取 demo/records.ts，关闭时为空 | 内存中的虚构数据，不写正式存储 |
| `startupGate.ts` | 本标签页是否已经从启动页进入系统，以及用户原本要打开的地址 | 浏览器的 `sessionStorage`（只在当前标签页有效）和内存 |

显示偏好由设置页和命令面板共同修改；演示开关控制比赛、记录、统计及记忆。运行快照和虚构业务数据只在内存中，浏览器持久存储只保存显示偏好，不保存报价、业务记录或密钥。

`App.vue` 使用 Vue 自带的 `KeepAlive` 保留 `ChatView`，切换页面后聊天历史与未发送输入仍在。聊天与任务需要刷新后恢复时，必须以服务端持久记录为准，不能仅靠前端内存。
