# 聊天提示词改版记录

每次改版由 `$chat-prompt-maintenance` 追加，最新的在最上面。离线测试要求锁文件里的每个版本都有一条 `### 版本号` 条目。

格式：

```markdown
## 日期｜一句话说明
- 原因：对应 issues.md 的编号，或一句话原因；不知道时写“原因待补”
- 静态提示词总字数：旧 → 新
- 回归试跑：未跑 / 日期与结果

### 新版本号（替换 旧版本号 / 新增 / 文字修正）
- 改了什么
- 字数：旧 → 新
```

## 2026-11-14｜接入近期战绩和 ESPN 伤病，分析写出数据推算和具体来源

- 原因：issues.md I-005（选场分析依据单薄、没有来源：服务端只给盘口和休息天数，实力、节奏、伤病几项只能写缺失或用 C 级泛泛判断）
- 静态提示词总字数：4465 → 6551（不含程序追加的时间与快照）
- 回归试跑：未跑

### chat_sources_v3（替换 chat_sources_v2）
- A 级按来源分成盘口（The Odds API）、赛程与战绩（BALLDONTLIE，新增 team_form）、伤病列表（ESPN 非官方，可能滞后）；依据要写出具体来源和采集时间。
- 本赛季战绩、近期状态、伤病等仍禁止用 C 级，改为“只能用 A 级或 B 级”。
- 新增例外：用户提供的伤病和 injuries 不一致时两者都列出，按出场不确定处理。
- 字数：466 → 679

### chat_odds_v4（替换 chat_odds_v3）
- 原有内容不变，新增 team_form 和 injuries 两节：各字段含义；games 少于 5 只作参照；listed 为 false 不等于全员可出场；stale 的含义；球员作用先看 comment，否则按 C 级并注明。
- 字数：1344 → 2280

### chat_method_v5（替换 chat_method_v4）
- 实力差距：战绩推算主队净胜分 = home_minus_away_avg_margin + 2（主场），与共识差 3 分及以上才算选边因素；节奏：两队 avg_game_total 平均与共识总分差 4 分及以上才算因素。门槛是初始值，未经数据验证。
- 伤病：可用 injuries；早于该队最后一场报告的缺阵已在战绩里，不重复计算；之后报告的 Out 算新伤病，Day-To-Day 只算不确定。
- 选边理由顺序加入“injuries 里的新伤病”和“战绩差”；已公布的伤病和休息差视为盘口通常已计入，只靠这两类时把握不超过“中”。
- 预计范围：战绩推算只决定调整方向和幅度，不替代共识线。
- 字数：853 → 1379

### chat_output_v4（替换 chat_output_v3）
- 因素表资料列写等级加具体来源（例如“A，ESPN 伤病某时采集，可能滞后”）；战绩一行写出所用数字和推算过程；“预计怎么来的”加入战绩推算一步。
- 把握分档：新增“战绩差”“新伤病”定义；“高”可由战绩差触发，“伤病已知”包括 injuries 可用且不过期；“中”加入新伤病和战绩差，新伤病与休息差同向仍为“中”；“低”加入战绩只作参照的情况。
- 字数：1552 → 1963
