# 维护代码库现状说明书

让接手项目的人先读一个简短父块，再按需要进入模块子块，知道代码在哪里、实际做到哪、哪些结论经过验证。默认父块为仓库根目录 `CODEBASE.md`，子块为 `docs/codebase/<module-id>.md`。用户或项目已有同类结构时沿用，不另建一套。

## 使用方式

- “用 $codebase-map 初始化这个项目的代码说明书”：先查看现有约定和代码，再生成父块与模块子块。
- “用 $codebase-map 同步本次改动”：核对这次受影响的模块及其调用方，更新子块，再同步父块。
- “用 $codebase-map 检查整个项目的说明书”：重新检查文件结构与所有已登记模块，报告未能核对的范围。

Skill 是执行这些工作的流程。开发任务调用它时才会运行；它自身不提供文件监听或定时执行。

## 先确定依据与范围

遵守目标代码库的 `AGENTS.md` 与交接约定。先读父块、相关子块；不存在时再初始化。阅读实际入口、接口注册、关键实现与配置，以代码判断现状。需求、README 和交接用来补充意图及历史证据，不能单独证明功能已经实现。

检查项目是否使用 Git（记录代码版本的工具）。有 Git 时记录当前 HEAD；核对自上次文档基准以来的提交变化、本次未提交和暂存的改动、未跟踪的新代码文件。只看最近一次提交或只看未提交改动，都可能漏掉变化。上次基准不存在或无法解析时，改为重新核对文件结构和模块，不初始化 Git 来绕过问题。

没有 Git 时：

- 对本次开发任务，按实际改动文件和调用关系做增量更新，并核对新增、移动的文件。
- 对独立的手动检查，先列当前源码文件结构，核对父块与每个子块登记的入口及实现；大项目可分批，明确已查和未查的模块。
- 文件时间只用来找候选变化，不作为功能状态依据。检查不完整时保留“部分核对”，不刷新全量核对日期。

默认跳过密钥文件、依赖目录、构建产物和批量运行数据；用不含秘密的配置示例了解变量。外部取数、付费接口、部署和业务数据修改不属于文档维护。验证需要这些操作时先说明，依现有授权处理；无法执行则如实记录边界。

## 初始化文档

从 [父块模板](assets/CODEBASE.template.md) 和 [子块模板](assets/module.template.md) 生成实际文档。替换模板变量，移除不适用的示例，不把模板占位符留在正式文档中。

按实际职责划模块，而不是给每个文件写一页；小项目可以只有少量子块。模块使用稳定的英文短名作为文件名，标题可以是中文。规模增长后再拆子模块，保持父子链接可追踪。

- 父块：项目用途、当前可用程度、模块摘要与链接、跨模块调用、重要缺口、核对范围与基准。详细参数放子块，避免复制后两处不一致。
- 子块：职责、入口和关键符号、输入输出、依赖、已实现与待实现、验证证据、限制和未决事项，以及返回父块的链接。
- 每个实际实现结论给出源码路径与函数、组件或注册位置；“测试通过”另列执行日期、命令、实际结果。读过代码只说明实现存在，不等于运行通过。
- 将“已实现 / 部分实现 / 仅预留 / 未实现 / 待核验”与“本轮运行验证 / 历史验证 / 仅查代码 / 未验证”分开记录，不给主观完成百分比。
- 拟议方案和下一步单列为建议，不写成当前架构。历史快照保留原采集时间，不描述成实时数据。

## 同步与维护

1. 先确认改动影响哪些模块、公开接口、依赖或运行命令；跨模块变更追到调用方，识别新增、迁移和已移除模块。
2. 核对受影响源码后改子块，再同步父块的摘要、状态和链接。只更新有依据的结论；疑点写“待核验”。模块已移除时标记停用并说明替代位置，删除文档依项目约定和用户授权处理。
3. 记录实际核对日期、范围和 Git 基准（若有）；未核对的子块保留原日期。增量更新不改变“最近全量核对”日期。若无实质内容变化，简短报告已检查的范围，不制造重复维护记录。
4. 检查父子链接、源码路径、状态是否一致；可运行既有的、与变更匹配且不调用外部付费服务的检查。不要为了证明文档存在而构建整站。

无法完成的检查保留原证据并标注原因；失败不能写成成功更新。不因为发现代码问题就修改业务代码，先记录发现，除非用户已经授权修复。

按目标项目约定写交接；若目标项目没有交接机制，不强加 `docs/handoff/`。最后给父块链接、改动模块和验证边界。

## 复制到其他代码库

把整个 `codebase-map/` 目录复制到目标仓库 `.agents/skills/`，保留 `SKILL.md`、`assets/` 和 `agents/`，然后在目标项目调用初始化。模板不固定技术栈、产品名、开发路径或模块数量；实例文档由目标代码生成。

如果用户希望 AI 每次开发后同步文档，可将以下规则追加到目标项目原有 `AGENTS.md`，保留原有内容；仅调用一次文档更新不代表授权安装协作规则：

```markdown
完成影响代码行为、接口、模块职责、依赖或运行方式的改动后，使用 $codebase-map 更新相关子块和 CODEBASE.md。只改交接或代码地图自身时不递归触发。手动编辑发生后，在下次开发任务或手动调用时同步。
```
