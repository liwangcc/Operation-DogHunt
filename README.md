# Operation DogHunt

以聊天为入口的 NBA 分析项目。前端采用 **Vue 3 + TypeScript + Vite + Vue Router**，后端采用 **FastAPI**。

Vue 负责页面；TypeScript 帮忙提前检查代码中的常见错误；Vite 负责启动开发页面和打包；Vue Router 负责页面之间的切换；FastAPI 负责后台接口。

## 当前可以做什么

当前配置：使用用户填写的项目独立 Key、`https://relay.example` 与 `gpt-6.1-sol`，真实网站后端已返回“项目模型连接成功。”。修改 `backend/.env` 后需重新加载后端；不读取或导入其他应用凭证。

- 打开网站先看到可旋转、缩放的 3D 指挥室启动页：点击“进入系统”进入下面的功能，也可以从左侧菜单或场景里的设备直接进入某个模块。同一标签页进入一次后不再出现，访问 `/welcome` 可以再看。声音默认关闭。
- 在启动页点“开始比赛 PLAY”，战术桌会变成球馆，可以用键盘或手柄打一场 3v3 街机篮球（WASD 移动、Shift 加速、J 投篮、K 传球、L 变向或抢断、Esc 暂停；防守时不按加速键会面向持球人滑步）。电脑对手的能力比玩家一方略高。只需启动前端。
- 进入系统后是延续启动页风格的深色控制台：左侧六个工位，顶部状态条显示盘口快照、模型配置、后端连接和北京时间，按 `Ctrl+K` 可以快速跳转。聊天首页和比赛与盘口用后端的真实数据，需要启动前后端。
- 预测记录、效果统计、长期记忆的界面已经做好，但后端还没有对应接口：默认用虚构的“沙盘联赛”演示数据预览，页面顶部有明确标注，可在设置里关闭，关闭后显示真实的空状态。只启动前端也能看这三页。
- 设置页显示真实的运行状态，并可调整只保存在本机浏览器里的显示偏好（赔率格式、默认报价平台、动态背景、演示数据）。
- 页面自动请求后端连通检查，在顶部状态条显示实际连接状态；失败时点一下可以重新检查。
- 填写本项目独立的模型配置后，在聊天页调用指定模型，直接询问已保存的比赛与盘口，或补充资料继续追问。
- 查看 FastAPI 自动生成的接口文档。
- 继续独立使用已有的手动盘口取数脚本。
- 在独立的“比赛与盘口”页面查看 NBA 已开盘比赛、北京时间、让分与大小分、两侧赔率，切换日期和报价平台；点击“更新盘口”手动获取新数据。选好平台后可点“交给 AI 分析”进入聊天。

**已接通模型聊天与保存盘口联动。** 每次提问由后端读取最新保存的快照，不会自动请求外部盘口；有选场时只提供所选比赛及平台，未选场但提到球队时只提供这些球队的比赛，否则提供已保存的全部比赛与平台；聚焦到少数比赛时附带后端算好的多平台共识、盘口变动和两队休息天数（赛程来自 BALLDONTLIE 免费档，更新盘口时顺带获取，需配置 Key）。回答逐段显示，中途失败的半截内容会被丢弃。过期数据仍是旧快照，需要在比赛页手动更新。聊天在页面切换时保留，刷新或关闭网站后清空。后端连接成功只表示 FastAPI 能响应；“模型已配置”只检查配置齐全，不会自动调用模型。实时比分、伤病查询、正式预测保存、数据库、长期记忆和后台任务仍未实现。

## 第一次启动

需要 Node.js `^22.18.0 || >=24.12.0`、npm、Python 3.12 或以上，以及 uv。uv 是管理 Python 依赖和项目独立运行环境的工具；依赖会安装到 `backend/.venv/`，不会装进系统 Python。

在项目根目录打开终端：

```sh
cd "/Users/x_hoon/Operation DogHunt"
make setup
```

`make setup` 根据 `frontend/package-lock.json` 与 `backend/uv.lock` 安装已锁定的依赖。锁文件像一张准确的配料表，让下次安装尽量保持一致。此命令需要联网，但不会调用体育或 AI 接口。

随后开两个终端，都进入项目根目录。

终端 1 启动后端：

```sh
make backend
```

终端 2 启动前端：

```sh
make frontend
```

打开 [本地页面](http://127.0.0.1:5173)，先出现启动页；点击“进入系统”后，右上角应显示“后端已连接”。要停止服务，在对应终端按 `Ctrl+C`。

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:5173` | Vue 开发页面 |
| `http://127.0.0.1:5173/welcome` | 3D 启动页，只需启动前端即可查看 |
| `http://127.0.0.1:5173/matches` | 独立比赛与盘口页面 |
| `http://127.0.0.1:8000/api/v1/health` | 后端连通检查 |
| `http://127.0.0.1:8000/api/v1/model` | 模型配置状态，不消耗额度、不返回密钥 |
| `http://127.0.0.1:8000/api/docs` | 自动生成的接口说明与试用页面 |
| `http://127.0.0.1:8000/api/openapi.json` | 接口格式的机器可读说明 |

`/api/docs` 的交互界面会从公共 CDN 加载 Swagger UI 资源；断网时可直接查看 `/api/openapi.json`。CDN 就是向浏览器提供公共页面资源的服务器。

## 配置与密钥

默认配置不需要任何 Key，就能启动页面；发送聊天需要配置模型。需要修改配置时：

- 后端：参考 `backend/.env.example` 新建 `backend/.env`；程序会按后端目录定位，操作系统环境变量优先。
- 前端：参考 `frontend/.env.example` 新建 `frontend/.env.local`，可修改开发时的后台转发地址；修改后重启前端。
- 已有盘口脚本：继续读取根目录 `.env.local` 中的 `THE_ODDS_API_KEY`，与模型配置独立。
- 赛程（可选）：在同一个 `.env.local` 加 `BALLDONTLIE_API_KEY=`（[app.balldontlie.io](https://app.balldontlie.io) 免费注册），更新盘口时后端顺带取近几天赛程存到 `data/schedule/`；不填则跳过，聊天里的休息天数显示为缺失。

### 中转站模型

模型使用本项目的 `backend/.env`，不读取 Codex 或其他应用的配置。原先复制的模型凭证已按用户要求清空，等待用户提供独立配置。文件权限为 `600`（仅当前用户读写），参考 `backend/.env.example` 填写：

- `DOGHUNT_MODEL_BASE_URL`：供应商给出的 API 根地址；程序在末尾添加 `/responses`。是否带 `/v1` 取决于供应商，不自动补齐。
- `DOGHUNT_MODEL_API_KEY`：中转站 Key，仅保存在后端。
- `DOGHUNT_MODEL_NAME`：用户在中转站选择的模型标识，必须与供应商支持的名称一致。
- `DOGHUNT_MODEL_REASONING_EFFORT`：控制模型在回答前投入多少思考，默认 `high`（高）；可设为 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`，具体档位须由所选模型和中转站支持。每次请求显式发送 `reasoning.effort`；不支持时会报错，不会自动降档。聊天与功能块共用此配置。
- `DOGHUNT_MODEL_EXTRA_HEADERS`：仅供应商明确要求时填写的额外认证头，JSON 格式，默认 `{}`；不从其他应用导入。
- `DOGHUNT_MODEL_TIMEOUT_SECONDS`：默认 120 秒，总等待时间受限制。
- `DOGHUNT_MODEL_MAX_OUTPUT_TOKENS`：默认最多生成 4096 tokens；tokens 是模型计算用量的文字单位，此预算同时包含思考与最终回答。极高强度可能增加等待和用量；若回答被截断，应结合预算和超时配置调整。

修改 `.env` 后重启后端，再点击页面“检查配置”。配置是独立副本，Codex 后续切换模型或更新认证不会自动同步到网站。

打开聊天页，输入真实资料或明确标记的假设资料并点击“发送”。每次发送会产生一次模型请求，带上当前页面的历史对话；不自动重试，同一后端进程同时只允许一个请求。默认每轮最多 20 次提问，单条最多 12000 字符、总上下文最多 60000 字符。异常后输入保留，可手动重试；超时不保证供应商未计费。

后台使用 Responses 流式接口，收到完整完成事件后再把回答交给网页，本阶段不是逐字显示。网页把回答当纯文本显示，不执行模型返回的 HTML。

浏览器请求 `/api/v1/health`，Vite 再把 `/api` 转发到 `127.0.0.1:8000`。这种转发像一个收发窗口，页面只需使用自己的地址，不必额外配置跨站访问。

**任何 API Key 都不能放到前端代码或 `VITE_` 开头的变量里**，这些内容可以被浏览器用户读到。三个位置的真实 `.env` 文件都由 `.gitignore` 排除，只有 `.env.example` 示例可以提交。

## 构建与本地检查

```sh
# 检查 TypeScript，然后生成 frontend/dist/ 页面文件
make build

# 后端聊天与中转兼容性离线检查，不消耗模型额度
(cd backend && .venv/bin/python -m unittest discover -s tests -v)

# 后端启动后，验证真实 HTTP 响应
curl --fail http://127.0.0.1:8000/api/v1/health

# 从前端入口检查转发链路，前后端都需启动
curl --fail http://127.0.0.1:5173/api/v1/health
```

默认响应：

```json
{"status":"ok","app":"Operation DogHunt","environment":"development","version":"0.1.0"}
```

构建后可运行 `npm --prefix frontend run preview`，在 `http://127.0.0.1:4173` 本地预览；连接检查仍需要启动后端。

当前命令只监听本机。尚未配置公网部署、登录保护或生产运行方式；Vite 的开发转发和 preview 不属于生产服务器。部署时需要让 `/api` 转发到 FastAPI，并让其他前端页面路径回到 `index.html`，以支持刷新 `/memory` 等页面。

## 已有盘口工具

侧栏“比赛与盘口”（`/matches`）提供比赛卡片，默认近 7 天，可切换今天、明天、全部已开盘；时间按北京时间显示。页面只读取已保存的快照，点击“更新盘口”才请求一次 The Odds API，通常消耗 2 credits，实际以页面返回为准。60 秒内不重复更新，无定时请求或自动重试；旧数据保留并标示采集与报价时间。

也可按 [API 取数使用说明](docs/API取数使用说明.md) 独立运行 `scripts/fetch_nba_odds.py`，网站复用它的取数和保存逻辑。数据保存在 `data/odds/`，部署时需携带该脚本。数据源仅覆盖已开盘比赛，空列表不能证明全天没有比赛。聊天每次发送时读取该目录最新快照，并保留来源、时间、主客方向和平台区分；前端只传比赛与平台标识，不传报价。已选比赛或平台在最新快照失效时，需重新选场或取消选择。

## 共同开发与敏感配置

项目源码、文档、`AGENTS.md`（项目协作规则）、`.agents/skills/`（项目 Skill 与模板）、依赖锁文件和示例配置均随仓库共享。文档中的 `https://relay.example` 是脱敏占位地址，不能直接用于连接。

真实 API Key、中转地址和额外认证只保存在本地 `.env` / `.env.local`，不上传。协作者按各目录的 `.env.example` 自行创建配置。依赖目录、构建产物和运行数据由 `.gitignore` 排除，安装和运行时自行生成。本机用户目录中的全局 Skill 与其他应用配置不属于本项目；项目需要共享的 Skill 已放在 `.agents/skills/`。

协作开发请为任务创建分支，完成后提交 Pull Request（把代码改动交给同伴检查、合并的申请）。仓库公开不等于所有人可直接修改，写入权限由仓库管理员单独邀请。
